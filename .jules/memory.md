## Archived: 2026-10-31

* When encountering `ERR_MODULE_NOT_FOUND` during tests, do not manually install missing production dependencies using `pnpm add`. Instead, ensure `pnpm install` is run in the correct workspace directory (e.g., `/app` or `/app/server`) to avoid bloating `package.json` and `pnpm-lock.yaml` with unrelated modules.
* Configure Square environments using an explicit `SQUARE_ENVIRONMENT` variable (set to 'production' or 'sandbox') decoupled from `NODE_ENV`, allowing staging environments to run against either environment seamlessly.
* Security input sanitization utilities for detecting NUL bytes, fullwidth digits/dots in hostnames, non-canonical IPv4 addresses, and ZIP header validation are centralized in `server/lib/security_sanitizer.js`.
* When styling text in the Splotch UI, use the 'Modak' font (--font-modak) for broader brand identity and main titles, and the cleaner sans-serif 'Baumans' font (--font-baumans) for utility interfaces and editors.
* For material terminology, keep internal identifier keys (e.g., 'pvc', 'pp') intact across API payloads and backend schemas to avoid breaking downstream scripts. Update only frontend display labels (e.g., mapping 'PVC' to 'Heavy-Duty Laminated Vinyl').
* The local Vite dev server (`pnpm run dev`) uses the `@vitejs/plugin-basic-ssl` plugin and binds to `https://localhost:5173/`. When writing Playwright verification scripts, navigate to `https` and ensure browser contexts are created with `ignore_https_errors=True` to avoid connection issues.
* Telegram security alerts are specifically triggered only for events with a 'CRITICAL' severity. Automated honeypot and sensitive path probes are intentionally logged as 'MEDIUM' or 'LOW' to allow tracking/blocking via Fail2ban without triggering Telegram alert fatigue.
* When styling canvas elements for image previews, use `object-fit: contain` instead of `fill` to preserve the aspect ratio of the content across responsive mobile viewports and prevent visual distortion.
* For machine-to-machine (agentic) checkouts, the architecture enforces an 'AND' condition combining an AP2 cart mandate ('x-ap2-mandate') for governance and a single underlying payment rail (like 'authorization-x402'). Do not use redundant, dual-protocol payment rails like combining MPP and x402.
* When testing Server-Sent Events (SSE) endpoints with Supertest, tests will hang if waiting for the full response because the connection stays open. To avoid timeouts, validate the connection establishment by asserting against the HTTP headers (e.g., 'content-type': 'text/event-stream') without awaiting the response body, or properly mock the stream closure.
* Append selected order tuning levers/tradeoffs (e.g., flexible filler, rush queue, no reprints) directly to the Square payment/order `note` field so fulfillment constraints are visible on printed packing slips.
* For AP2 and x402 agentic payments, existing system credentials can be reused instead of generating new ones: `JWT_PUBLIC_KEY` can be used for `AP2_GOVERNANCE_PUBKEY`, `SQUARE_LOCATION_ID` for `X402_MERCHANT_ID`, and `SQUARE_ACCESS_TOKEN` for `X402_API_KEY`.
* When adding focus states or other styling improvements, the codebase strongly prefers using existing Tailwind utility classes (e.g., `focus-visible:ring-2`) over injecting custom CSS into style blocks.
* The Developer/PeerJS Status indicator should be kept in the DOM for troubleshooting but hidden by default via CSS (`display: none`). Reveal it dynamically only when a debug flag is present (e.g., `?debug=true` or `localStorage.getItem('debug') === 'true'`).
* When adding dynamic event listeners to the `document` in frontend scripts (e.g., click-outside handlers for UI components), assign the handler function to a stable window property (e.g., `window._closeDropdownListener`) to ensure it can be cleanly removed via `removeEventListener` and to prevent duplicate firing or memory leaks across re-renders.
* For AP2 agentic payments, the `x-ap2-mandate` can include an `agentRules` object (e.g., `{ maxSpendCents, expiresAt }`). When enforcing spending limits, always compare `maxSpendCents` against the securely stored `storedQuote.total` from the database, never the self-reported `req.body.amount`.
* The production environment runs bare-metal via systemd (`splotch.service`) without Docker. Security features and routing rules must be implemented directly in the Express application (`server/server.js`) rather than relying solely on `nginx/nginx.conf`, which is only active in containerized or proxied setups.
* To mock built-in Node.js modules (like `fs`) in Jest for ES Modules, use `jest.unstable_mockModule('module_name', ...)` alongside `jest.resetModules()` before dynamically importing the module under test.
* When implementing Model Context Protocol (MCP) servers over SSE in Express, expose two separate endpoints: a GET route (e.g., `/api/mcp`) to establish the SSE stream, and a POST route (e.g., `/api/mcp/messages?sessionId=<id>`) to receive incoming JSON-RPC calls from the client.
* When writing Jest tests for ES Modules that use module-level variables for caching state, call `jest.resetModules()` before dynamically importing the module (`await import(...)`) to ensure a fresh, un-cached instance is evaluated for each test block.
* To prevent exposing sensitive files to credential scanners, do not use `dotfiles: 'allow'` in `express.static` middleware. Instead, use `dotfiles: 'ignore'` (or `'deny'`) and handle allowed hidden paths (like `.well-known`) explicitly via routing or security middleware.
* The security alerting system (`server/lib/securityAlerts.js`) logs multi-strike events (repeated IP offenses) by appending attempt counts to the log detail string without escalating the severity, avoiding redundant Telegram alerts while preserving Fail2ban tracking/blocking capabilities.
* For AP2 agentic payments, the server's public governance key (`AP2_GOVERNANCE_PUBKEY`) is publicly exposed at the `/.well-known/ap2` endpoint as a JSON object containing the `pubkey`, `capabilities` (e.g., `['x402']`), and `mandate_formats` (e.g., `['sd-jwt', 'jwt']`).
* When handling custom vector cutline uploads, avoid programmatic failure detection heuristics as they often create false positives on complex, high-detail sticker perimeters.
* Always use `pnpm` for package management in this repository; never use `npm` or `yarn`.
* Agentic payments require `X402_MERCHANT_ID`, `X402_API_KEY`, and `AP2_GOVERNANCE_PUBKEY` environment variables to be configured for x402 settlement and AP2 governance.
* The DigitalOcean deployment process uses a cloud-config file located at `docs/digitalocean-cloud-config.yml`, which provisions the server and injects environment variables into `/home/loki/.env`.
* The project's `SVGParser` (`src/lib/svgparser.js`) relies on browser APIs like `DOMParser` and `document`. When using it in server-side Node.js environments for asset preflight or processing, polyfill these globals using `jsdom` (e.g., `global.DOMParser = new JSDOM().window.DOMParser`).
* For maximum screen-reader compatibility and mobile usability, explicitly associate HTML labels with their respective inputs using the `for` attribute, rather than relying solely on ARIA labels or implicit wrapping.
* Place touch-friendly mobile toolbars for the canvas directly beneath the canvas rather than floating over it, to prevent obscuring sticker edges during touch interactions like pinch, drag, or rotate.
* The frontend checkout supports digital wallets (Apple Pay and Google Pay) using the Square Web Payments SDK. This requires dynamic updates to `paymentRequest` based on cart totals (`currentOrderTotalCents`) before tokenization.
* For x402/AP2 agentic payments, x402 keys (`X402_MERCHANT_ID`, `X402_API_KEY`) are obtained from a payment facilitator (e.g., Square, Coinbase CDP, Stripe), while `AP2_GOVERNANCE_PUBKEY` is the public half of a self-generated asymmetric key pair (e.g., RSA or ECDSA) used to sign AP2 payment intents (Checkout JWTs).
* The UI and codebase distinguish between `stickers` (compositional elements on the canvas, managed in `src/lib/stickers.js`) and `printInks` (print-specific material layers or masks for a sticker).
* To avoid execution timeouts when running unit tests, specify the target test file (e.g., `pnpm run test:unit tests/image-processing.test.js`) rather than running the entire test suite.
* Visual and cutting properties like `cutlineOffset`, `cutlineSensitivity`, `lazyLassoRadius`, `isGrayscale`, and `isSepia` are defined as properties on individual `sticker` objects to ensure they are applied per-sticker rather than globally.
* When implementing Model Context Protocol (MCP) servers over SSE using '@modelcontextprotocol/sdk', manage 'SSEServerTransport' instances dynamically (e.g., mapped by 'sessionId') to properly handle concurrent connections, rather than storing a single global transport.
* In `GeometryUtil.getRotatedPolygonBounds`, caching rotated bounds in a non-enumerable `_rotatedBoundsCache` Map on the polygon object eliminates redundant trigonometric calculations during nesting searches. Safe handling for frozen/non-extensible objects requires using optional chaining (`polygon._rotatedBoundsCache?.get(angle)`) and catching `defineProperty` errors without failing.
* Do not write Playwright (e2e) tests for AP2 or MCP integrations. They are headless machine-to-machine (M2M) protocols and should be fully covered by unit and HTTP integration tests.
* For Splotch UI styling, prefer subtle Tailwind shadows (e.g., shadow-sm, shadow-md) over heavy custom borders to maintain a clean and flattened visual hierarchy.
* For agentic checkout API endpoints, never trust pricing data (e.g., 'amount') submitted in the client payload. Always validate the 'quoteId' against server-side storage to confirm the correct price and check expiration before processing the order.
* The official AP2 repository is primarily Python and reference specifications. Define necessary AP2 schemas and types directly in Node.js (e.g., via Zod or JSON Schema) instead of attempting to pull a Python/external package.
* The server's WooCommerce integration explicitly requires `WOOCOMMERCE_CONSUMER_KEY` and `WOOCOMMERCE_CONSUMER_SECRET` to be configured (via environment variables or the database). If omitted, the system proactively fails authentication (e.g., returning 401 Unauthorized for API routes or 500 for OAuth handshakes) rather than falling back to default/hardcoded secrets.
* In the `lowdb` database architecture (`server/database/lowdb_adapter.js`), collection properties like `db.data.orders` are stored and managed as objects indexed by ID (e.g., `db.data.orders[order.orderId] = order;`), not as arrays.
* When running Playwright frontend verification scripts, ensure blocking overlays such as the login modal (`#close-modal-btn`) are conditionally closed or waited upon before interacting with the main UI components.
* In `src/index.js`, `doRedrawAll()` uses fixed default dimensions (`DEFAULT_CANVAS_WIDTH = 500`, `DEFAULT_CANVAS_HEIGHT = 400`) when the canvas is empty (`!hasContent`) to prevent padding feedback loops from causing continuous canvas expansion.
* When managing Model Context Protocol (MCP) servers over SSE, ensure the HTTP request's 'close' event handler explicitly calls 'await sseTransport.close()' before removing the session to properly clean up resources and prevent memory leaks.
* The `.Jules/palette.md` file serves as a dedicated journal for recording critical UX and accessibility learnings and constraints.
* For machine-to-machine payments, x402 and AP2 act as authorization and signaling protocols; actual funds settlement relies on underlying payment gateways like Square tokenized payments or crypto rails (e.g., USDC, Lightning).
* Use the `jose` library to cryptographically verify signatures on incoming AP2 mandates (`x-ap2-mandate`, `x-ap2-intent`). When handling SD-JWT formats, explicitly extract and verify the base JWT.
* When adding dependencies to specific workspaces using pnpm, ensure the command is executed correctly from the workspace root (or verify the lockfile diff) to prevent unintentionally dropping existing package resolutions from pnpm-lock.yaml.
* To run Jest unit tests with ES Modules in this repository, set `NODE_OPTIONS='--experimental-vm-modules'` (e.g., `NODE_OPTIONS='--experimental-vm-modules' pnpm run test:unit <test-file>`).
* When adding new API endpoints in `server/server.js`, ensure they are mounted under a rate-limited path like `/api` or applied after the `apiLimiter` middleware to prevent bypassing rate limits.
